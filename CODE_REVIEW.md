# Scripra code review

Reviewed September 7, 2026 (America/Chicago). Scope: current working tree, including existing uncommitted changes; Next.js routes, authentication, dashboard, capture/demo flows, subscription state, marketing interactions, Chrome extension, configuration, and standalone HTML prototypes. This is a static review with selected local mock reproductions, not a deployed penetration test or a live meeting interoperability certification.

The current implementation is a product prototype with production blockers in capture, persistence, authentication configuration, email dispatch, and billing. Several customer-facing success states represent simulations rather than completed operations. Marketing demonstrations can reasonably use sample data, but authenticated customer workflows need an explicit boundary between sample and real data.

P1 means address before a production launch. P2 means a concrete functional or security issue to fix subsequently. Findings are grouped by severity, not implementation order.

1. **[P1] Require authentication and server-owned entitlements before sending recaps.** [send-recap/route.ts](C:/AIworkX/2026/Scripra/Code/src/app/api/meetings/send-recap/route.ts:26). The route never checks a session, accepts arbitrary recipients, and defaults the request-controlled `isProUser` field to true. The proxy protects only `/dashboard`. An anonymous POST containing only an attendees array reaches the Resend dispatch when a key is configured, permitting unauthorized use of the sender and email quota. A local mock reproduced HTTP 200 and one outbound dispatch without credentials or `isProUser`. Check the session, workspace permissions, stored subscription, recipient policy, and sending limits on the server.

2. **[P1] Validate login callback URLs before client navigation.** [login/page.tsx](C:/AIworkX/2026/Scripra/Code/src/app/login/page.tsx:20). `callbackUrl` comes directly from the query string and is passed to `router.push`, including immediately for an authenticated visitor. A crafted `/login?callbackUrl=...` can redirect off-site or supply a `javascript:` URL. The installed Next.js useRouter documentation explicitly warns that such URLs can execute in the page context. Resolve against the application origin, require an allowed same-origin HTTP(S) destination, and reject unsupported schemes before any navigation. Auth.js's redirect handling does not protect this separate client-side push.

3. **[P1] Remove the publicly known fallback session secret.** [auth.ts](C:/AIworkX/2026/Scripra/Code/src/auth.ts:45). If both secret environment variables are absent, production uses a constant committed to source. Knowledge of this secret permits constructing valid Auth.js session tokens rather than requiring legitimate authentication. Fail startup when a production secret is absent and rotate the secret for any deployment that has used the fallback. This finding is conditional on deployment configuration; secret values were not inspected.

4. **[P1] Keep one speech recognizer per capture lifecycle.** [LiveMeetingStudio.tsx](C:/AIworkX/2026/Scripra/Code/src/components/LiveMeetingStudio.tsx:283). The initialization effect depends on `durationSeconds`, which increments every second. It repeatedly replaces `recognitionRef.current` without stopping the previous instance. Stop therefore targets a new, never-started recognizer; the original can continue listening and uses its original timestamp closure. A local mock confirmed that the started instance was never stopped after one timer update. Initialize once, read changing metadata/time through refs, and stop/abort the actual active instance on Stop and unmount. Generate the final recap after final recognition results have arrived.

5. **[P1] Prevent the extension caption observer from observing its own updates.** [content.js](C:/AIworkX/2026/Scripra/Code/extension/content.js:162). Deduplication remembers only the last text globally while each callback rescans every caption node. With two distinct visible captions, every callback adds both again. Updating the overlay counter also mutates the observed body subtree, producing further callbacks without new speech. A bounded mock produced eight appended turns from four callbacks over two unchanged nodes. This can grow memory/storage writes and stall Meet. Track changes per caption/utterance and restrict observation to caption containers while excluding Scripra's overlay.

6. **[P1] Persist ingested meetings and resolve detail pages by ID.** [ingest/route.ts](C:/AIworkX/2026/Scripra/Code/src/app/api/meetings/ingest/route.ts:29). The endpoint returns a success ID but neither saves segments nor generates a recap. The extension opens that ID, while [the detail page](C:/AIworkX/2026/Scripra/Code/src/app/dashboard/conversations/[id]/page.tsx:8) always renders the same hardcoded transcript; IDs only affect labels and the export filename. Conversation lists, search, decisions, and actions also use independent sample arrays. Saving a real meeting therefore yields unrelated sample content, and the captured transcript is lost when its tab closes. Implement user/workspace-scoped persistence and retrieval, or explicitly restrict these paths to a labeled demo until that exists.

7. **[P1] Establish an actual meeting audio source before showing a connection.** [LiveMeetingStudio.tsx](C:/AIworkX/2026/Scripra/Code/src/components/LiveMeetingStudio.tsx:340). Entering a Meet, Zoom, Teams, or Webex URL only changes the status to “Listening”; it does not connect to the call or acquire its audio. The only capture source started is local microphone SpeechRecognition, and all recognized speech is assigned to the organizer. With headphones, remote attendees are not captured through that microphone. Implement a supported audio/caption bridge and speaker attribution, or describe this mode accurately as microphone transcription and do not report a connected meeting.

8. **[P1] Report email failures as failures.** [send-recap/route.ts](C:/AIworkX/2026/Scripra/Code/src/app/api/meetings/send-recap/route.ts:203). Provider rejection, network exceptions, and missing configuration return success with simulated receipt IDs. Separately, [the client catch block](C:/AIworkX/2026/Scripra/Code/src/components/LiveMeetingStudio.tsx:515) sets `sent: true` even when the request itself fails. The UI then says the recap was delivered. Return non-success results for failed dispatch, preserve retryable content, and make an explicitly selected simulation mode distinct from delivery. Also distinguish provider acceptance from confirmed inbox delivery.

9. **[P1] Route contact submissions to a real inbox or durable queue.** [contact/route.ts](C:/AIworkX/2026/Scripra/Code/src/app/api/contact/route.ts:80). Even with a configured key, all messages go to `delivered@resend.dev`, not the Scripra team. Without a key, or after provider errors, the route claims the inquiry was captured/queued without storing its contents. The form clears the user's message after that success. Local mocks confirmed both the fixed recipient and a successful no-key response. Configure the intended recipient, persist submissions if queueing is promised, and propagate failures to the form.

10. **[P1] Replace simulated checkout before claiming an active paid subscription.** [UpgradeModal.tsx](C:/AIworkX/2026/Scripra/Code/src/components/UpgradeModal.tsx:31). Checkout merely waits one second, changes local state, and announces an active subscription. There is no payment operation or verified webhook. [SubscriptionContext](C:/AIworkX/2026/Scripra/Code/src/context/SubscriptionContext.tsx:34) trusts a browser-local plan; Settings also lets customers choose any tier. Every account in the same browser shares that plan key. Keep the simulator explicitly isolated from customer billing, integrate a real checkout and verified subscription updates, and derive entitlements from authenticated server data.

11. **[P1] Do not invent decisions or consensus in real recaps.** [LiveMeetingStudio.tsx](C:/AIworkX/2026/Scripra/Code/src/components/LiveMeetingStudio.tsx:230). Every nonempty transcript gets a 92% consensus score and a claim that follow-ups were agreed, regardless of what participants said. Takeaway categories are assigned by utterance position, including labeling the third utterance a Decision. A meeting explicitly rejecting a proposal still receives an agreement claim. Implement evidence-based extraction or omit unsupported fields; keep deterministic demonstration claims out of real meeting records and emails.

12. **[P1] Reset transcript and delivery state when starting a new meeting.** [LiveMeetingStudio.tsx](C:/AIworkX/2026/Scripra/Code/src/components/LiveMeetingStudio.tsx:320). Start resets the timer and hides the recap but retains `turns`, prior recap/actions, attendees, and the previous send receipt. Stop and then Start without manually clearing produces a new session whose recap/export includes the previous session's transcript under the new timing/title. This can also send old meeting content to a new recipient list. Define separate New Meeting and Resume operations, reset session-owned state for New Meeting, and preserve old sessions separately when required.

13. **[P1] Stop demo microphone capture when navigating away.** [demo/page.tsx](C:/AIworkX/2026/Scripra/Code/src/app/demo/page.tsx:79). The recognition effect has no cleanup, and `onend` automatically restarts unless Stop was clicked. Starting the demo and following an internal navigation link can leave its recognizer active after the recording controls disappear. On unmount, mark the session stopped, disable restart callbacks, and abort the recognizer. This is independent of the studio's per-second replacement bug.

14. **[P2] Use a production-configurable extension application URL.** [content.js](C:/AIworkX/2026/Scripra/Code/extension/content.js:250). Ingestion and every dashboard navigation in content.js, popup.js, and background.js are hardcoded to localhost:3000. An installed extension on a customer's computer will contact that customer's machine rather than the deployed service. Configure a consistent HTTPS application origin and matching extension permissions, with localhost limited to development.

15. **[P2] Do not substitute fabricated transcripts or claim nonexistent local saves.** [content.js](C:/AIworkX/2026/Scripra/Code/extension/content.js:218). Save MoM with no captions silently substitutes a fictional conversation, including deployment approval. If ingestion throws, the catch block reports “Saved locally,” although only metadata, not transcript segments, is written to extension storage. Reject empty captures with actionable feedback; retain recoverable transcripts before acknowledging a local save. Test dialogue should be explicitly marked and confined to a demo path.

16. **[P2] Escape user-controlled HTML in outgoing emails.** [send-recap/route.ts](C:/AIworkX/2026/Scripra/Code/src/app/api/meetings/send-recap/route.ts:107). Titles, transcript-derived text, tasks, owners, translations, and URLs are interpolated directly into HTML. The contact email uses the same pattern for names and messages. User content containing markup can inject deceptive links/layout into a branded email; quotes in URL attributes can alter the markup. A mock dispatch preserved an injected `<b>` element unchanged. Escape text and attribute values and validate link schemes. This finding concerns HTML/content injection; arbitrary script execution in recipients' email clients was not tested or assumed.

17. **[P2] Actually translate recaps into the selected language.** [LiveMeetingStudio.tsx](C:/AIworkX/2026/Scripra/Code/src/components/LiveMeetingStudio.tsx:234). Every non-off language returns the original purpose prefixed with Spanish “Resumen ejecutivo,” regardless of the selected target. Choosing French or Japanese therefore displays and emails untranslated content labeled as that language. Connect a translation implementation with explicit failure handling, or disable the selector until available.

18. **[P2] Submit investor requests before reporting memo delivery.** [InvestorsSection.tsx](C:/AIworkX/2026/Scripra/Code/src/components/InvestorsSection.tsx:160). The request form only schedules a local success state after 800 ms. Nothing sends the email or records a lead, yet the success message promises a dispatched confidential memo and founder follow-up. Implement a real submission path and accurate queued/sent/error states so investor leads are not silently lost.
